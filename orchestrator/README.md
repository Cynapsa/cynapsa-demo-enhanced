# Enhanced Orchestrator agent

This is an ordinary FastAPI/LangGraph app (`app:app`) with POST `/ask`. It uses a LiteLLM-compatible model, calls Maps at `/maps` and optionally Files at `/files`, and stores conversation checkpoints in a private SQLite directory. Its own application code imports no Cynapsa SDK: `cynapsa run` maps the HTTP origins to peer IDs and runs the ASGI app without an application HTTP listener.

The wire mesh ID is `demo_enhanced_cynapsa_demo`. Configure `DEMO_MAPS_AGENT_ID`, `DEMO_FILES_AGENT_ID`, and `DEMO_CLIENT_AGENT_ID` in the role environment. The default origins are `http://maps-enhanced.local`, `http://files-enhanced.local`, and `http://client-enhanced.local`; these are Cynapsa mapping aliases, not DNS endpoints. The CLI profile ID is `demo-enhanced-orchestrator`. Keep its enrollment and LiteLLM credentials out of the repository and image. Do not reuse the regular demo's profile.

Fill `.env` from `.env.example`, then use `./run.sh --build` and `./run.sh` for a local role container. Stop the old process before `./run.sh --force-enroll`. The image builds SDK/Core from their `demo-enhanced` branches; verify exact commits at `/opt/cynapsa/source-revisions`. The separate AWS deployment is ECS service `demo-enhanced-orchestrator` in cluster `cynapsa-demo-enhanced`, `us-east-1`. Local rebuilds do not update that service.

The app logs `[cynapsa]` requests, responses, and bounded downstream errors; the CLI logs confirmed mesh events. Model HTTP access logs are reduced to warnings. Client-facing unexpected failures are generic, while the orchestrator terminal records the actual public Cynapsa error code without a Python traceback. Full request/response bodies appear in logs, so use demo-only content. The default Cynapsa mode has no application HTTP listener; ordinary HTTP mode requires `DEMO_HTTP_ACCESS_KEY` and a trusted ingress boundary.
